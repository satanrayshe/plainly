Least-privilege policy

The agent's permissions (infra/agent-iam-policy.json, attached as plainly-agent-policy) cover only the services Plainly uses, only for plainly-* resources, only in us-east-1. Roles it creates must carry the plainly-boundary permissions boundary. An explicit deny applies whenever a call arrives through the MCP server (aws:ViaAWSMCPService is true): the agent cannot delete stacks, buckets, tables or IAM entities, stop or delete a CloudTrail trail, or create users and access keys.

We tested the deny on purpose. The agent asked, through MCP, to delete a stack:

cloudformation:DeleteStack  StackName=plainly-mcp-guardrail-test   (via AWS MCP Server)
AccessDenied: User: arn:aws:iam::********1486:user/plainly-agent is not authorized to perform:
cloudformation:DeleteStack on resource: arn:aws:cloudformation:us-east-1:********1486:stack/plainly-mcp-guardrail-test/*
with an explicit deny in an identity-based policy: arn:aws:iam::********1486:policy/plainly-agent-policy

The same user deleting a failed stack from the plain CLI at 15:07 was allowed. The deny is about the agent acting through MCP, which is the point. Creating IAM users and granting permissions was left to the account owner: Claude Code's own permission check stopped the agent from doing it, and the owner ran infra/setup-agent-user.sh instead.

Not done in time: a dedicated CloudTrail trail with MCP data events, and the deny-only lock policy described in infra/README-infra.md. Event history covers management events for 90 days.
